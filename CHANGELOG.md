# Changelog

All notable changes to this project are recorded here, in [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) form.

## [Unreleased]

### Added

- The `deploy-modal` workflow deploys `deploy/modal_app.py` on pushes to `main` that change the app's code or dependencies, after lint and tests pass. Its Modal token is an environment secret of `modal-deploy`, which only `main` can use, so a pull request cannot read it. There is no approval step: anyone who can push to `main` can deploy. Its actions are pinned to commit SHAs.
- `predmark run --venue kalshi-demo` and `predmark status --venue kalshi-demo`. A strategy pass can send orders to Kalshi's demo exchange through `Engine`, with demo market data, the default `RiskLimits` and its own journal (`<name>.kalshi-demo.sqlite`). It reconciles before trading and places no orders on a mismatch. `open_paper` became `open_engine(..., venue)`. Production is not a venue option.
- `python -m predmark.execution.demo_check`, which runs the order lifecycle on the demo exchange: rest, cancel, fill, close, and a lost send response that `reconcile()` resolves after a restart. It is tested offline against the paper venue, including fills that arrive late. It passed on the demo exchange on 2026-11-11, and so did a 5-entry Nothing Ever Happens pass with `--venue kalshi-demo`.

- Kalshi subaccounts. `KalshiVenue(subaccount=n)` names its subaccount on every order, cancel and portfolio read, the primary included, because Kalshi's order and fill listings default to all subaccounts. `DEMO_SUBACCOUNTS` gives each demo journal its own subaccount (1 for `demo_check`, 2 for Nothing Ever Happens, created and funded on the demo account on 2026-11-11). Before this, a demo strategy journal took in `demo_check`'s fills, because both traded in one account. The two demo journals from before the change were renamed `*.pre-subaccounts`.
- `Engine` binds a journal to the venue account it first trades on (`venue_account` in its meta) and raises `JournalAccountMismatch` if it is opened against another. Offline readers pass `bind_account=False`.
- `demo_check` picks only markets on exchange index 0, where its subaccount has funds.
- Shard funding. Kalshi funds each exchange index separately and refuses orders on an unfunded one. `KalshiVenue.shard_balances()` reads cash per index, and Nothing Ever Happens skips markets on an unfunded index (`pass.unfunded`) instead of stopping its pass at the first refusal. `python -m predmark.execution.demo_accounts` lists balances, creates subaccounts and moves cash between subaccounts and indexes on demo. Demo subaccount 2 got $10 on index 2 on 2026-11-11, and a 30-entry demo pass then filled on both indexes.

### Changed

- The `site` workflow no longer holds a Modal token, which could reach the whole Modal workspace. The Modal app has a new `run_logs` web endpoint, public and read-only, that serves only the `*.runs.jsonl` files the site already publishes. The workflow reads it with `python -m predmark.site --from-url`, from the repo variable `RUN_LOGS_URL`. Run log names in the response must be bare `*.runs.jsonl` names, so a bad response cannot write outside the state directory. `--from-modal` stays for local builds.
- Paper fills and the Nothing Ever Happens backtest charge a direct Kalshi account's fee: the formula rounded up to $0.0001, not to the cent. Kalshi's fee rounding docs and every demo fill on 2026-11-11 agree. A one-contract NO entry at 0.2¢ now pays $0.0002, not $0.01. Paper journals keep the fees they were charged, so paper P&L has a step at this change. `kalshi_fee` still defaults to the cent grid, because the committed E001 to E003 analyses and the E003 preregistration use it. E001 and E002 used 100-contract lots, where cent rounding adds under 0.01¢ per contract, so their results stand without an erratum.

### Fixed

- `KalshiVenue.place` reported a partly filled immediate-or-cancel order as filled, because Kalshi reports remaining 0 once it cancels the rest. A full fill is now judged by the fill count. Found on demo, where a 1-contract order filled 0.42. The journal's fills were always right; only the order status and the pass summary were wrong.
- `Engine.reconcile()` acted on Kalshi's order and position listings straight after an order changed. Those listings trail the matching engine by 0.3 to 0.7 seconds on demo, so a fresh resting order could be marked cancelled in the journal (undercounting exposure), and a just-cancelled order halted the engine as unknown. Now, if a first read disagrees with the journal, reconcile waits the venue's `listing_lag_seconds` (2 s for Kalshi, 0 for paper) and acts only on a second read.
- `python -m predmark.research check-integrity`, run in CI by the `research-integrity` workflow on pull requests and pushes to `main`. It fails if any commit removes or changes a line of `research/trials.jsonl`, if a `results.json` is not committed strictly after its experiment's `preregistration.md`, if a preregistration differs from the version its ledger entries hashed, or if a paper in `research/papers/` fails `check-paper`. E001 is exempt from the commit-order check only, because it was run before the repo's history began and its prereg and results arrived in one commit. Its ledger hashes still match its preregistration.
- `predmark.jev`, a client for TypeSafe's Jev through its REST API (`POST /v1/systemone`), not the Vercel AI Gateway, which documents only a TypeScript SDK call. It pins `jev-1.14.0`, retries only 429, 529 and connection failures (requests that were never evaluated), and has a spend cap per client and a JSONL cost log in `data/jev/`. `python -m predmark.jev` has `models`, `ping` and `spend` commands. `TYPESAFE_API_KEY` is in `.env.example`. Checked live on 2026-11-08: the server adds about 265 input tokens to each request, so the spend cap's upper bound adds a margin for it.
- `predmark.collect`, a registry and runner for daily data collections. Each collector writes under `collect/<name>/` in the state directory and logs each run to `runs.jsonl`. They run in the daily Modal job after the strategies, and one failing does not stop the others. `python -m predmark.collect list | run`.
- `jev-forecasts`, the first collector. It records Jev's probability that each market in the Nothing Ever Happens universe resolves YES, the listing quote, and the bet that implies at a 5-cent margin after fees. No bet is placed. This is the data for E003, preregistered on 2026-11-08. The Modal secret `typesafe-jev` holds the key.
- `kalshi-listing`, a collector that snapshots the quote, sizes and 24-hour volume of every Kalshi market above the Nothing Ever Happens volume threshold each day, with its volume rank, to `collect/kalshi-listing/snapshots/<date>.jsonl.gz`. Kalshi serves no historical listings, so this lets a backtest replay what the live run saw.
- E003 preregistration (committed 2026-11-11, unchanged since 2026-11-08), and its `fetch.py` and `analyze.py`, tested on synthetic data with a planted edge and a null. `fetch.py` pulls outcomes for one split at a time and refuses holdout outcomes before 2027-03-07. `analyze.py` refuses the holdout before then and after its first evaluation.
